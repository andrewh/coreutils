# Source layout

This page lists the top-level directories and explains how the build knows
which source files make up each program.

## Top-level directories

| Directory | Contents |
|---|---|
| `src/` | One main `.c` file per program (147 `.c` files in total), plus modules shared by several programs and their headers. |
| `lib/` | Generated by `./bootstrap`. Holds the gnulib modules copied into the tree. A fresh clone has only `lib/local.mk` and a few files. |
| `gl/` | Modules written for coreutils but packaged the gnulib way (`gl/lib/`, `gl/modules/`), for example `randint`, `heap`, `mbbuf`, `root-dev-ino`. |
| `gnulib/` | Git submodule with the gnulib sources. `./bootstrap` fills it in. |
| `tests/` | Test scripts, mostly in one directory per program (`tests/cp/`, `tests/sort/`, ...). `tests/misc/` holds tests for small programs. |
| `doc/` | The Texinfo manual (`coreutils.texi`), which is the user documentation. |
| `man/` | Man pages. These are made from each program's `--help` output with `help2man`, plus optional `man/PROGRAM.x` additions. |
| `build-aux/` | Build helpers, for example `gen-lists-of-programs.sh`. |
| `m4/` | Autoconf macros used by `configure.ac`. |
| `docs/` | These notes (MkDocs). Not part of upstream. |

## Which programs get built

`build-aux/gen-lists-of-programs.sh` is the single list of programs. It sorts
them into four groups:

| Group | Meaning | Examples |
|---|---|---|
| `disabled_by_default_progs` | Not built or installed unless you pass `--enable-install-program=NAME` to `configure`. | `arch`, `coreutils`, `hostname`, `kill`, `uptime` |
| `build_if_possible_progs` | Built only if `configure` finds the system features they need. | `df`, `stdbuf`, `libstdbuf.so`, `who`, `users`, `stty`, `timeout` |
| `build_if_appropriate_progs` | Built everywhere but useful only on some systems (SELinux). | `chcon`, `runcon` |
| `normal_progs` | Everything else. | `cat`, `cp`, `ls`, `sort`, ... |

!!! tip
    `uptime` and `kill` were added to this list in 9.10 (see `NEWS`). Many systems install these programs from other
    packages (for example `procps` and `util-linux`), but `NEWS` does not say
    why the change was made.

## How a program's sources are listed

`src/local.mk` is included by the top-level `Makefile.am`. By default
Automake builds program `src/foo` from `src/foo.c`. When a program needs
more files, `src/local.mk` lists them with a `src_foo_SOURCES` line. The
table shows the main cases.

| Program(s) | Extra sources | Why |
|---|---|---|
| `cp`, `mv`, `install` | `copy.c`, `copy-file-data.c`, `cp-hash.c`, `force-link.c` (`$(copy_sources)`), `selinux.c` | All three copy files. |
| `mv`, `rm` | `remove.c` | Recursive removal. `mv` needs it to finish a cross-device move. |
| `chown`, `chgrp` | `chown-core.c` plus `chown-chown.c` or `chown-chgrp.c` | One source, two programs. |
| `ls`, `dir`, `vdir` | `ls.c` plus `ls-ls.c`, `ls-dir.c` or `ls-vdir.c` | Each small file sets `ls_mode`. |
| `uname`, `arch` | `uname.c` plus `uname-uname.c` or `uname-arch.c` | Each small file sets `uname_mode`. |
| `md5sum`, `sha*sum`, `b2sum`, `sum`, `cksum` | `cksum.c` with `-DHASH_ALGO_*=1` | One source, many programs. |
| `base64`, `base32`, `basenc` | `basenc.c` with `-DBASE_TYPE=...` | Same idea. |
| `cut`, `numfmt` | `set-fields.c` | Parsing of field lists such as `1,3-5`. |
| `df`, `stat` | `find-mount-point.c` | Finding the mount point of a file. |
| `tail`, `tee` | `iopoll.c` | Detecting a broken pipe on output. |
| `split`, `tac` | `temp-stream.c` | Spooling non-seekable input to a temporary file. |
| `date`, `du` | `show-date.c` | Formatting a time stamp. |
| `id`, `groups` | `group-list.c` | Printing a list of groups. |
| `ln`, `realpath` | `relpath.c` (and `force-link.c` for `ln`) | Relative path computation. |

Some programs also link small SIMD helper libraries. These are built with
special compiler flags only when `configure` finds the CPU support:

- `cksum`: `libcksum_pclmul.a`, `libcksum_avx2.a`, `libcksum_avx512.a`
  (x86) and `libcksum_vmull.a` (ARM).
- `wc`: `libwc_avx2.a`, `libwc_avx512.a` (x86) and `libwc_neon.a` (ARM).

The program checks at run time which version the CPU supports. See
[cksum](../commands/cksum.md) and [wc](../commands/wc.md).

## Single-binary build

`./configure --enable-single-binary` builds one executable, `src/coreutils`,
that contains every program. `src/coreutils.c` chooses the program in this
order:

1. The last part of `argv[0]` (so a symlink or hard link named `ls` runs
   `ls`). The name `install` is mapped to `ginstall`.
2. A first argument `--coreutils-prog=NAME`, or
   `--coreutils-prog-shebang=NAME` for use in `#!` lines.

During this build each program's `main` is renamed to
`single_binary_main_NAME` with a `-Dmain=...` compiler flag. The flag comes
from `build-aux/gen-single-binary.sh`. `launch_program()` in
`src/coreutils.c` calls the renamed function. On Linux it first calls
`prctl(PR_SET_NAME)` so that `ps` shows the right name.
